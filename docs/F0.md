# F0 — Pieslēgšanās / reģistrēšanās sistēmā: prasības apraksts

Oct 14, 2026 · @Arvīds Vilčaks

## Pamatinformācija

F0 nodrošina, ka CRM dati pieejami tikai pieslēgtam lietotājam. Lietotājs var izveidot kontu, pieslēgties un atslēgties; pēc pieslēgšanās viņš nonāk vadības panelī (F9).

| Lauks | Vērtība |
| --- | --- |
| ID | F0 |
| Nosaukums | Pieslēgšanās / reģistrēšanās sistēmā |
| Veids | Funkcionālā prasība |
| Statuss | Izpildīts (CR-4) |
| Atkarīga no | — (priekšnoteikums N3 un visām pārējām funkcijām) |
| Jāatbilst | N1 (pieejamība), N2 (personas dati), N4 (tehnoloģijas) |

## Mērķis un lietotāji

Pieslēgšanās identificē lietotāju, lai serveris katrā pieprasījumā varētu noteikt viņa lomu (N3) un rādīt tikai atļautos datus.

| Loma | Ko var darīt | Piezīme |
| --- | --- | --- |
| Nepieslēgts apmeklētājs | Atvērt reģistrācijas un pieslēgšanās lapu | Jebkura cita lapa novirza uz `/auth/login`, API atbild 401 |
| Darbinieks / Vadītājs | Pieslēgties, atslēgties | Jauns konts vienmēr saņem lomu „Darbinieks” (N3) |

## Pieņemšanas kritēriji / negatīvie gadījumi

| # | Ievade | Sagaidāmais rezultāts |
| --- | --- | --- |
| 1 | Derīgs vārds, e-pasts, 12+ rakstzīmju parole | 201; atbildē nav paroles; loma „darbinieks” |

| 4 | Parole īsāka par 12 rakstzīmēm | 422 |
| 5 | Ķermenis nav derīgs JSON objekts | 400 |
| 6 | Pareizi pieslēgšanās dati | Sesija izveidota; forma novirza uz `/panelis` |
| 7 | Nepareiza parole vai nezināms e-pasts | 401, abos gadījumos vienāds ziņojums |
| 8 | Atslēgšanās, pēc tam `/panelis` | Sesija dzēsta; novirza uz pieslēgšanās lapu |
| 9 | Datubāzes un žurnālu pārbaude pēc reģistrācijas | Parole glabāta tikai kā sāļota jaucējvērtība; žurnālos paroles nav |

## Pieejamība (N1)

- Formas veidotas ar kopīgo makro `_formas.html`: katram laukam `label for`, obligātie lauki marķēti „(obligāts)”.
- Kļūdu gadījumā virs formas ir kopsavilkums ar `role="alert"` un saitēm uz kļūdainajiem laukiem; laukiem `aria-invalid` un `aria-describedby`.
- Pieslēgšanās kļūda „Nepareizs e-pasts vai parole.” ar `role="alert"`; ziņa par izveidotu kontu ar `role="status"`.
- Laukiem ir `autocomplete` (`name`, `email`, `username`, `current-password`, `new-password`), paroles prasība parādīta kā palīgteksts.

## Personas dati (N2)

- Paroli glabā kā PBKDF2-SHA256 (200 000 iterācijas) ar 16 baitu nejaušu sāli; salīdzina ar `hmac.compare_digest`.
- Parole netiek atgriezta nevienā atbildē un netiek rakstīta žurnālos.
- Sesijā glabā tikai `lietotajs_id`; lomu un vārdu nolasa no datubāzes katrā pieprasījumā.
- Sākumdatu lietotāju parole nāk no vides mainīgā `CRM_SAKUMDATU_PAROLE`; repozitorijā paroļu nav.

## Tehniskā realizācija (N4)

- **Maršruti:** `GET /auth/register`, `POST /auth/register` (201/409/422), `GET /auth/login`, `POST /auth/login` (200/401/422), `POST /auth/logout` (204/303), `GET /` (303). API maršruti aprakstīti `docs/openapi.yaml`.
- **Ievade:** `crm/ievade.py` (`nolasit`) pieņem gan JSON, gan HTML formu; formas kļūdas atgriež to pašu lapu ar 422/409/401.
- **Sesija:** Starlette `SessionMiddleware` (`crm/app.py`): sīkdatne `crm_sesija`, parakstīta, `HttpOnly`, `SameSite=Lax`, derīga 8 stundas; atslēga no `CRM_SESSION_SECRET`, `Secure` ar `CRM_HTTPS=1`.
- **Atkarības:** `pieslegts_lietotajs` / `Pieslegts` aizsargā maršrutus; `NavPieslegts` apstrādā `crm/kludas.py`.
- **Faili:** `crm/auth.py`, `crm/paroles.py`, `crm/templates/auth/registreties.html`, `crm/templates/auth/pieslegties.html`, tabula `lietotaji` (`crm/shema.sql`).
- **Testi:** `tests/test_cr4_pieslegsanas.py`.
